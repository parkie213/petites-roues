# Endpoint and operation inventory

Historical baseline, reviewed 13 November 2026 at workspace commit `27962b2`. This records the current
implementation and proposes boundaries for the
[state migration](STATE-AND-CONCURRENCY-PLAN.md). PR #79 changes monitor ownership
but not this route set. The five selected consolidations are now implemented; see [HTTP-API.md](HTTP-API.md)
for the current 58-route surface. The tables below preserve the original baseline.

For the full list regrouped by capability and a more aggressive consolidation
proposal, see [ENDPOINT-CONSOLIDATION.md](ENDPOINT-CONSOLIDATION.md). That proposal
revises the initial recommendations below, particularly for typed edit commands,
study-state loading and progress.

## Scope and evidence

The inventory covers **80 explicit HTTP method/path combinations in 15 controllers**,
including the two paths on the pending-review handler. Implicit HEAD/OPTIONS,
framework error handling, static assets and browser page routes are excluded.
Routes come from controller annotations and `PhoneRoutes` constants. Callers were
traced through all JavaScript/TypeScript source extensions, preparation scripts,
agent workflows, shared phone client code and server/browser tests. “No production
caller found” is repository evidence, not proof that external scripts never use it.

Current admission is `/api/**` on the local UI listener and `/phone/**` on the phone
listener, enforced by filters in one application context. Only phone pairing is
unauthenticated within the phone routes; other phone requests authenticate a bearer
and update last-seen state. Target admission separates the contexts structurally.

The current React entry point is `web/src/app/main.jsx` → `App.jsx`.
`library/Repositories.jsx` has synchronous API calls but is not imported by that
entry graph. `web/server.mjs` still accepts `/repositories` as a page route; the
current React router renders Page not found there. Do not count that component as
an active second management UI.

Include accepted manifest identity in derived cover version, rather than live document stats. |
| Q | Build chapter quiz — ChapterQuizService | POST is computation, not persistence; loads effective comic then uses pure shared builder. | Capture accepted effective document + version, compute outside transaction; return revision with result for stale-response handling. |
| S | Synthesize speech — SpeechService / PiperSynthesizer | Title route reads effective document for language; supplied text is not checked against a cue. Preview has no title dependency. Decide explicitly whether title speech must bind supplied text to a document revision. |
| T | Select voice — SpeechService | Check installed files, autocommit settings upsert, then reread installed voices/preferences. | One settings operation; filesystem validation outside transaction, no document version change. Return saved preference independently of subsequent listing. |
| H | Browse/download voice resources — VoiceCatalogueService | Synchronized catalogue/cache/install; GET catalogue may fetch and write disk cache. Separate install progress/cancellation work from state migration unless required by a demonstrated issue. |
| F | Choose local file/folder — SystemFileDialog | Opens native dialog and waits; no persistent domain mutation. | Retain local-only operation with no DB transaction; path selection itself never registers content. |
| Z | Configure phone listener — PhoneListener | Lifecycle monitor opens/closes connector then separately persists setting. | W | Read Markdown notes/quizzes — MarkdownPageService | Reads repository list, scans notes/quizzes directories and reads live Markdown on each request. ## Consolidation decisions

1. **Keep domain-specific edit commands.** Cue, timing, split/merge, comic line and
   box operations encode different validation and identity guarantees. The
   [consolidation proposal](ENDPOINT-CONSOLIDATION.md) puts those typed commands
   behind one acceptance endpoint with a common version/retry contract. A generic
   JSON PATCH endpoint would hide the rules rather than remove them.
2. **Use one discovery workflow with scheduling outside it.** Synchronous repository
   endpoints and POST /api/jobs currently expose the same Add/Refresh work through
   different completion contracts. The current browser uses jobs. Keep the
   synchronous endpoints while tests/preparation/manual tooling are migrated;
   decide whether external agents require a synchronous adapter before retiring
   them. Do not maintain separate discovery implementations.
3. **Retire the `/changes` alias after checking external callers.** It is exactly the
   same handler as `/review-queue`, with no in-repository production caller found.
   It is the clearest redundant route. No compatibility reader or new alias is
   needed for the new state model.
4. **Keep `/comic` distinct from a plain document read for now.** It validates the
   archive manifest, whereas GET title only loads the document. Share the accepted
   read underneath; do not drop that validation while deduplicating code.
5. **Share export state, retain transport-specific responses.** GET title, export
   and phone document delivery should read the same accepted state. Attachment
   headers, phone canonical bytes and comic-open validation are adapter concerns.
   Do not wrap exported portable JSON in local revision fields; use response
   headers or a separate application response contract.
6. **Keep library projections and media identities.** Flat catalogue supports
   preparation lookup; hierarchical library and poster shelves serve different
   browser views. Title-relative and fingerprint-relative media routes distinguish
   annotated and bare media. Redirect/version pairs implement caching, not duplicate
   business operations. Consolidate their reads, not their meanings.
7. **Keep validation separate from publication.** `/validate` is safe, read-only
   candidate inspection. It cannot guarantee that a later publication still has
   the same expected base. Completion becomes the atomic publication operation;
   adding another independent publish endpoint would duplicate authority unless
   there is a separate, defined non-review use case (Refresh already imports files).
8. **Keep app-facing and agent-facing routes on the local listener.** Review
   operations are used by agents, but review requests are also preparation-script
   operations and pending state feeds the player. Share application services; no
   new MCP adapter is justified by this inventory. Phone endpoints get their own
   route context and reuse read services rather than local HTTP endpoints.

## Cutover checklist

- [ ] Define how application responses carry content revision and title state
  version without changing portable document JSON or breaking playerDocument().
- [ ] Define stale-state conflicts, mutation retry identities and committed-result
  responses across edits, review completion and discard. Timing saves currently
  return only `{ok, lines}`, while most edits return a whole document; comments
  change queue state without changing the document. All need a usable state receipt.
- [ ] Define coherent player loading: it currently fetches document and queue in
  separate requests, and comic loading separately fetches document and progress.
  Choose combined application state where needed or explicitly reconcile versions;
  a transaction inside each endpoint does not make two requests one snapshot.
- [ ] Capture all accepted-document consumers: normal read, comic open/images,
  fallback cover generation/versioning, exports, review pending/claim, edit
  validation, comic progress validation, chapter quizzes, speech language and phone
  listing/download. No live-file reconstruction path may remain in these operations.
- [ ] Decide Markdown publication scope (W). If live notes/quizzes stay, document
  their independent consistency and atomic-file-writing contract. Do not claim all
  content reads are database snapshots while these endpoints still scan files.
- [ ] Keep large resource streaming, native work, dialogs, probing and disk
  measurements outside transactions; distinguish cache writes from learner writes.
- [ ] Define job admission when another job is running. It currently returns the
  running job even if the new requested work differs. The response must not imply
  the new operation was accepted or committed; preserve or revise this deliberately.
- [ ] Coordinate per-repository Refresh All outcomes with job result fields and the
  old synchronous API/tests. An HTTP 202 or a finished task is not a persistence
  receipt for every requested target.
- [ ] Migrate prepare/app.py, agent review documentation, browser consumers, shared
  phone protocol tests and the static demo service worker with changed contracts.
  The demo emulates API responses without the server and is a real contract consumer.
- [ ] Inventory integration-test setup before removing synchronous routes; fixtures
  currently depend on Add/Refresh endpoints. Distinguish fixtures from product use.
- [ ] Verify route isolation with both listener contexts, including forged Host,
  absent Origin, failed bind, ephemeral ports and requests in flight during close.

## Verification and bounded next task

This is a source inventory, not a live-server route or authentication test. Extracted
controller/PhoneRoutes method/path combinations were compared with the catalogue
for completeness; local documentation links and whitespace were checked. No runtime
or API contract was changed, so application test suites were not rerun for this work.

The next design deliverable is one worked request/response example for a cue split
and a batch publication with a later pending edit. Resolve version propagation,
retry receipts and the Markdown scope decision before schema implementation. Phone
route isolation remains an independent implementation stage. Broad package/module
changes and endpoint removals are outside this inventory.
